# Video Platform — локальный каркас

Минимальная платформа генерации видео для localhost: промпт → улучшение
промпта → превью-картинка → черновое видео → финальное видео, с системой
кредитов и подменяемым провайдером.

## Запуск

```bash
cd video-platform
npm install
cp .env.example .env   # уже есть VIDEO_PROVIDER=mock — работает без ключей
npm run dev
```

Откройте http://localhost:3000.

## Что уже работает "из коробки"

`VIDEO_PROVIDER=mock` (значение по умолчанию) **реально генерирует**
PNG-превью и MP4-клипы через `ffmpeg` — это не заглушка-картинка, а
настоящий файл с анимированным градиентом и подписью вашего промпта,
подписанный `[MOCK DRAFT/FINAL]`. Это позволяет проверить весь пайплайн
(очередь, списание кредитов, историю) без единого реального запроса к
платному API. Требуется `ffmpeg` в `PATH`.

## Как подключить реальную генерацию (APIMart)

1. Зарегистрируйтесь на [apimart.ai](https://apimart.ai) и пополните
   баланс (минимум $1).
2. В `.env`:
   ```
   VIDEO_PROVIDER=apimart
   APIMART_API_KEY=ваш_ключ
   ```
3. **Важно:** `lib/providers/apimart.ts` написан по типовой схеме
   REST video-API (создать job → опрашивать статус → скачать результат),
   но **не проверен** против реальной документации APIMart — у меня не
   было доступа к их сайту из этого окружения. Перед использованием:
   - сверьте пути эндпоинтов (`/generations` и т.п.) и формат ответа с
     актуальными доками APIMart;
   - проверьте ID моделей в `MODEL_IDS` и тариф в `RATE_PER_SECOND_CENTS`
     (в коде — ориентиры из открытых источников на октябрь 2026, не
     первоисточник);
   - протестируйте на $1-5, прежде чем давать доступ пользователям.

Чтобы добавить другого провайдера (fal.ai и т.п.), скопируйте
`lib/providers/apimart.ts` как шаблон и зарегистрируйте его в
`lib/providers/index.ts`.

## Улучшение промпта через DeepSeek (опционально)

Если задать `DEEPSEEK_API_KEY` в `.env`, короткий запрос пользователя
перед генерацией превью переписывается в подробный промпт (сцена,
камера, свет, движение). Без ключа промпт используется как есть.

## Архитектура

```
app/
  page.tsx            — UI: промпт + 3 карточки этапов (превью/черновик/финал)
  history/page.tsx     — список всех прошлых генераций
  api/
    generate/          — POST { stage, prompt, parentJobId } — запускает этап
    jobs/, jobs/[id]/   — чтение истории/статуса задачи
    media/[id]/[file]/  — отдаёт сгенерированный файл
    credits/            — баланс + демо-пополнение
lib/
  db.ts               — SQLite (файл data/app.db), создаётся сам при первом запуске
  credits.ts          — списание/пополнение, баланс никогда не уходит в минус
  jobs.ts             — оркестрация одного этапа: улучшить промпт → сгенерировать → списать
  prompt-enhance.ts   — вызов DeepSeek (или passthrough)
  providers/
    types.ts          — интерфейс VideoProvider
    mock.ts           — бесплатный провайдер на ffmpeg (по умолчанию)
    apimart.ts         — заготовка реального провайдера (см. выше)
```

## Важные осознанные ограничения

- **Один локальный пользователь** (id=1), без регистрации/логина — это
  демо для вашей машины, а не мультипользовательский продукт. Таблицы
  в SQLite уже спроектированы с `user_id`, так что добавить реальных
  пользователей позже — вопрос добавления auth, а не переделки схемы.
- **Кредиты списываются только после успешной генерации**, по
  реальной стоимости от провайдера — никогда заранее и никогда больше,
  чем провайдер фактически насчитал.
- **Деньги в демо-пополнении виртуальные** — `/api/credits` POST — это
  заглушка вместо платёжного шлюза (Stripe/Kaspi и т.п.), сделана для
  локального теста, не для прод-оплаты.
